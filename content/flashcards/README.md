# Flashcard vocabulary learning assets

These illustrations and English pronunciation files supplement existing vocabulary; they do not create or replace stories or words.

- Original SVG artwork: `illustrations/`, generated by `scripts/generate-flashcard-assets.mjs` and rendered to `public/images/flashcards/` with the project's Sharp dependency.
- English pronunciation: `public/audio/flashcards/`, synthesized using the installed Microsoft Zira Desktop English voice at rate -2. `scripts/generate-flashcard-audio.ps1` requires Windows System.Speech and ffmpeg.
- `manifest.json` maps existing English terms to these assets. Multiple occurrences of a term share the source illustration and recording.
- Runtime media links use the existing `/media/` route and private media storage. Reproducible UUID keys include each vocabulary row ID and field name. Original IDs and all text are retained.

Review the illustrations and recordings before adding new terms. Quiz alternatives must have different English terms, Vietnamese terms and pictures.

Dry-run enrichment: `node --env-file=.env.supabase scripts/enrich-flashcard-content.mjs`. Add `--apply` to upload and fill only missing media fields. For the local D1/R2 store, use `node scripts/enrich-flashcard-content.mjs --local --apply`. Each applied run writes a vocabulary snapshot to the ignored `.data/flashcard-content/` folder first; existing media is never overwritten.

Learning progress lives only in the device backup, under `flashcards`. Old version-one backups without that field remain readable. A progress key combines the story slug and normalized English/Vietnamese words, so re-saving a story with new vocabulary row IDs preserves its review schedule.

Run the scheduling and backup tests with `node --experimental-strip-types --test tests/flashcards-unit.mjs`. The browser runner accepts a site URL and `--words <sanitized-vocabulary-snapshot.json>`; it uses isolated Playwright contexts and closes its owned browser in `finally`. Add `--layout-only` for the result-screen visual check.

The matching game at `/tro-choi/ghep-tu-voi-hinh` uses this same story vocabulary and media, with no extra database tables. It requires a picture and both word labels; English audio is optional. Story/favorite filters apply before duplicate words and pictures are removed. Sessions use up to twelve distinct words in up to three rounds, with two to four pairs per ordinary round.

Matching results live in the device backup under `matching`, keyed by language and the same stable word identity. English and Vietnamese matching results remain separate from each other and from the Flashcard review schedule. Retry practice keeps the original first-try result. Run the matching and backup checks with `node --experimental-strip-types --test tests/matching-unit.mjs`; `tests/matching-browser.mjs` checks touch, drag, keyboard, audio, backup/restore and the existing Flashcard flow in isolated browser contexts.
